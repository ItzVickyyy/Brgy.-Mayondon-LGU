## Security and data protection
- **Health condition encryption (213):** `core/field_crypto.py` `EncryptedText` (AES-GCM, HKDF, stored `enc1:` + base64url). Key `DATA_ENCRYPTION_KEY` in `.env` (32+ bytes, separate from `MFA_ENCRYPTION_KEY`). No key = plain text (a missing key must not stop issuing); unreadable value = `[cannot be read]`. `app/migrate_on_start.py` calls `protect_health_conditions()` (failure logged, never stops start-up). The key sits beside the database: it protects a copied database or dump, not someone controlling the computer. Backups hold ciphertext, so a restore needs the matching `.env`. Names, addresses and birthdates stay plain on purpose. Provisioning: `install.ps1` (new), `scripts/ensure-data-key.ps1` (old; also run by `update.ps1`); both are in `verify-release-archive.sh`'s must-exist list.
- **Key rotation (215):** `rotate_secrets_cli --parts data-key` (by name only): checks every value opens, re-encrypts in one transaction, commits only after `.env` is replaced, rolls back on failure. After `apply` the OLD `.env` no longer opens health conditions; keep the old `.env` with older backups.
- **Bell reminders** (`components/Common/useSetupReminders.tsx`, dialogs in `NotificationBell.tsx`; administrators only): `dataKey` (orange no key, red unreadable; `GET /system/data-protection` returns `key_configured`, `plain_count`, `unreadable_count`, `active_admin_count`; counts photos), `secondAdmin` (exactly 1), `plainHttp` (non-localhost `http:`, snooze 14 days), `backupStale` (orange 3 days, red 7 days or none; `BACKUP_STALE_DAYS`/`BACKUP_URGENT_DAYS`), `update` (only while the watcher is fresh). Permission `system.status` is admin-only (`ADMIN_ONLY` in `test_rbac.py`). Bell panel 25 rem; severity colors red / amber / blue with `data-severity` values unchanged.
- **Sign-in:** per-account lockout (5 failures, 15 min) plus per-address limit (`core/login_throttle.py`, 20 per 15 min, 429). Default password `ChangeThisPassword` (`core/security.py` and `frontend/src/config/site.ts` must stay equal). Every authenticated route refuses a temporary-password user except `GET /users/me`, `PATCH /users/me/password`, the preferences endpoints and `POST /login/logout` (`test_temporary_password.py` `EXEMPT`).
- **One account, one computer (259–264; decision 103):** newest sign-in wins. `user.active_session_jti` (migration `a2f6c9e4b731`, never in `UserPublic`) is set in `_finish_login` (also MFA); `get_current_user_allow_temporary` answers 403 `signed_in_elsewhere` for another `jti` when `SINGLE_SESSION_PER_ACCOUNT` (default true; NULL = no limit until next sign-in). Frontend `isSignedInElsewhere()` (`lib/queryClient.ts`) → `/login?elsewhere=1`. `compose.yml` true; `compose.override.yml` and `tests/conftest.py` off (browser tests share one admin; developers set it false, `docs/07`, `docs/12`; `tests/test_single_session.py` turns it on). To simulate a pre-migration account clear the jti with a real `update(User)` then `expire_all()`. `_replaces_live_session()` logs `auth.session_replaced` (old jti not revoked and previous `auth.login` younger than `ACCESS_TOKEN_EXPIRE_MINUTES`). Open: owner may prefer "refuse the second sign-in".
- **Real sign-out:** `POST /login/logout` stores the token `jti` in `revokedtoken` until expiry; frontend `lib/endSession.ts`. Tokens last 8 hours; idle sign-out 30 minutes (`IDLE_MINUTES`, build-time).
- **CSP:** `_content_security_policy()` in `main.py`; the one inline script in `index.html` is allowed by hash (a new inline script or outside resource needs a console check). `/docs` and `openapi.json` only when `FASTAPI_ENV == "development"`. CSV export is formula-safe (`core/csv_safe.py`, `csvSafe()`).
- **HTTPS (220, decision 101):** default for new installs; an existing `.env` decides (re-running never switches an installed computer). `scripts/enable-https.ps1` (`-HttpsHost`, `-Off`; tests use `-EnvFile -EnvOnly`) changes only `COMPOSE_PROFILES`, `HTTPS_HOST`, `APP_BIND`, `FORWARDED_ALLOW_IPS`, saves `.env.before-https-<time>`, restarts, opens ports 443/80, runs `export-https-root.ps1`; `trust-office-https.ps1 -CertFile` on each computer. Behind Caddy keep `FORWARDED_ALLOW_IPS=*`.
- **Not done on purpose:** backend container runs as root (a safe design: start as root, fix `/backups` ownership, drop to an unprivileged user with `setpriv`; deliver only after a build test on the second laptop). No bell reminder for the `.env` USB copy. 23 `bun audit` advisories need major upgrades; `pip-audit` clean.
- **Office side:** second administrator, two-factor for everyone who can push to `Production`, a proven restore (needs `.env` with the data key), who reads the Activity Log.

## Speed (patches 221, 255)
- **Back end (221):** fast (3–10 ms per endpoint, dashboard ~100 ms; Argon2 ~200 ms, deliberate, do not weaken). `field_crypto` streams photos; `protection_status_cached()` 300 s per worker (tests set 0). `main.py`: `CompressTextOnly` (gzip ≥ 1 KB; skips images, fonts, zip, `.enc`, `/photo`, `/api/v1/backups/`); hashed `/assets/` (`_HASHED_ASSET`) one-year `immutable` (keep fixed names out), HTML `no-cache`; `/vision/selfie-segmentation/*` cached a day only for a 200 non-HTML answer. `tests/test_speed_helpers.py`.
- **Front end (255):** `lib/queryClient.ts` holds `queryClient`, `handleApiError`, `CURRENT_USER_KEY`, `currentUserQueryOptions` (`staleTime` 60 s), `loadCurrentUser()` (route guards; reads `/users/me` directly and must NOT use `fetchQuery`, whose 401 triggers a hard reload to `/login` and loops `login.spec.ts`) and `clearCurrentUser()`. `hooks/useDeferredStart.ts` (1000 ms) gates the bell query, `useSetupReminders`, `useDataProtection`. `routes/_layout/index.tsx` exports `dashboardQueryOptions(period)` and a prefetching `loader`. `main.tsx`: `defaultPreload: "intent"`, `defaultPendingMinMs` 120.
- **Test rules learned:** measure a pop-up only after `waitUntilSettled(dialog)` (`tests/utils/settled.ts`); wait for the row and use `exact: true` ("Restore" matches "Prepare Restore"); after `goto`/`reload` wait for the User menu and page button before pressing keys; let pop-up motion settle or allow tolerance in geometry checks; measure text with `Range.getClientRects()` (`dashboard-legend-fit.spec.ts`), not element boxes; shared-admin specs (`login`, `idle-sign-out`, `user-settings`, `preferences`, `interactions`, `two-factor-banner`) clash in parallel: judge failures with `--workers=1` on a fresh database.
- **Not done, by value:** (1) Activity Log queries: measured, no index yet (decision 104). (2) First visit loads ~25 tiny chunks. (3) Suspected: `GET /backups/` and `/system/update` read the shared folder, slow on Docker Desktop for Windows; ask the owner when slow sign-ins happen and which page. - Files in the shared `backups` folder connect the container to Windows: `update-state.json` (`up_to_date|available|updating|failed`), `update-watcher.json` (heartbeat 20 s), `update-request.json` (from `POST /system/update/request`). `scripts/update-watcher.ps1` (task "Mayondon Auto Update", at log-on) installs only in the night window (`-NightFrom` 02:00, `-NightHours` 3), checks GitHub every 3 hours, runs `auto-update.ps1 -Now` on a request. `auto-update.ps1` installs only what `Production` points to. `MAYONDON_CLOCK` and `MAYONDON_WAIT_FACTOR` are set only by tests.
- Installed version = `.installed-commit` (only `auto-update.ps1` writes it), else `full` in `frontend\build-info.json`; ignored if equal to `failed_sha`. Not seen: GitHub's own archive zip filling `export-subst`.
- Backend `routes/system.py` (`GET /system/update`, `POST /system/update/request`; 409 when the watcher is not running, nothing waiting or already updating), `core/update_state.py`, permission `system.update`, audit `system.update_requested`. Frontend `components/Updates/` (footer Close `data-testid="update-close"`).
- `update.ps1` tags `backend:previous` only from a healthy backend; the way back is `docker tag backend:previous backend:latest` + `up -d --no-build --force-recreate backend`; after a healthy update it prunes images. For USB updates build the folder with `git archive`. The first hop from an old install still runs the old `update.ps1`. Open: whether 02:00–05:00 suits the barangay; no staff notice that the program is updating.

## Deployment and data safety
- Office deployment: offline LAN, Windows 10/11, Docker Desktop; the office computer is an installed copy, not a clone. Generate new secrets per installation; **never copy `.env` between computers**; restore only from a verified encrypted backup.
- Backups use public-key encryption when `backups/backup-public.pem` exists; the private key and passphrase are separate, never committed, never in `.env`, never in chat. The restore script stages the key and backup under `backups/` and removes plaintext in a `finally`.
- Keep branch protections; accounts that can push to `Production` should use two-factor. The repository is public: two Word certification templates with real names still sit in history (blank copies exist since 194; remove the originals only with the owner's say-so). Do not delete, rewrite history or assume a committed database dump is safe without inspection. Synthetic data only in development and tests.
- **Backups (228, 233, 234):** `create_backup` records a failure unless the file is in the folder after the move; page warns when a recorded backup has no file; "last backup"/`daysSinceGoodBackup` ignore `file_exists` false. `verify_backup` leaves status alone for an unseen file (`MISSING_FILE_MESSAGE`); `heal_missing_file_failures()` (in `GET /backups/`) restores rows failed only for that. Verify shows only for `ok` + `file_exists`. Suspected cause: Docker Desktop file sharing (unproven). **Open:** if "File no longer in the backup folder" shows, note the time and run `docker compose -f compose.yml exec backend ls /backups`. Premigrate files not listed by design.

## Deceased residents (327; decision 117)
- `residents.status` is `active|archived|deceased`. **Never test `== "archived"` to mean "not usable"**: use `!= "active"` or handle both. A new list, count or report of residents or their documents must decide what it does with `deceased` (counts use `active`; `expiring_records` and `GET /barangay-ids/` leave deceased out). `_refuse_frozen()` and `_require_active()` are the guards; everything that changes a resident or issues to them locks and re-reads the row first (`_locked_or_404`, `issue()`, the masterlist update), and an `async` route does that in `run_in_threadpool` (a lock wait on the event loop can hang the server). The Barangay ID log import leaves deceased matches out.
- `resident_deaths` rows are never updated except to void them; correct = void + new row (flush the void first, partial unique index `uq_resident_deaths_current`). `status = deceased` exactly while one row is in force; change both only in `routes/residents.py`. Permission `records.deceased` (admin only). Audit `resident.death_record|death_correct|death_void`; details hold codes and field names, never the date or note. Downgrading the migration is refused while rows exist.
- **No cause of death**, also not as a hint to type it into `source_note` (it is returned in lists and not encrypted).
- **Screen (328):** Records has a **Deceased** tab for everyone (`DeceasedResidentsView.tsx`, server sort `death_date|death_evidence|death_recorded_by`; age at death is computed, not sortable). Only administrators see Record death (row menu of an active resident and profile footer), Correct death record and Void death record (row menu and profile footer of a deceased one). `RecordDeathDialog.tsx` is a plain dialog with no password step (like Archive; decision 117): date known to day, month, year or not at all, Reported/Verified, optional source note (500 chars, no `<>` or line breaks), a reason when correcting, and Save stays disabled while nothing changed. `lib/deaths.ts` repeats the server's date rules and must stay equal to them. A void asks for a reason in `ConfirmDialog`. A deceased profile shows `deceased-banner`, a Death record section, no running age and no Edit; New Issuance blocks anything but `Active`. Never add a cause-of-death field to this dialog. Specs: `deceased-records.spec.ts`, `table-fit`, `selection-no-shift-tables` (Deceased is tab 2, Barangay IDs tab 3), `residents-sort-server`.
