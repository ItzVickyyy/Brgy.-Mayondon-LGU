## Rules

1. **Record every work session.** Planning, coding, documentation, testing, debugging, reviews, meetings, AI-assisted work and small achievements.
2. **Record date, time and timezone** as `YYYY-MM-DD HH:MM (Asia/Manila, UTC+08:00)`. For older work without a reliable time, write "Time not recorded" instead of guessing.
3. **Write what you personally did.** Separate your contribution from a teammate's work, an AI suggestion or a team outcome.
4. **Record outcomes and evidence.** Paths, commit/PR links, test commands and results, issue IDs. Say clearly when a test was not run or is pending.
5. **Record AI usage.** Name the tool, what you asked it to do, what context you gave it at a high level, how you reviewed the output, and what you changed or verified yourself.
6. **Record blockers and next steps.**
7. **Be factual and useful** so a teammate can understand it later.
8. **Never put secrets or real resident data in a journal** (no passwords, tokens, API keys, private environment values, or identifying client/resident information).

Journals are working records, not a substitute for approved requirements, testing instruments or official project documents. Copy the template below for each entry; keep entries in chronological order, newest at the bottom.

- **Date:**

### Goal
What were you trying to accomplish, and why?

- What did you personally do?
- Which files, components, documents, tests or workflows did you work on?
- What investigation or decisions were made?

### Achievements / outcome
- What changed or was learned? What is complete, and what remains?
- Link commits, pull requests, issue records or bug-log IDs.

### AI tools and workflow
- **Tools used:** e.g. ChatGPT, Claude, GitHub Copilot, or none.
- **How they were used:**
- **Prompting / handover workflow:**
- **Human review:** how you inspected, tested, corrected or validated the output; what you decided yourself.
- **Limitations:** what was not verified or remains uncertain.

### Tests and verification
- **Checks run:**
- **Results:** Passed / Failed / Not run / Pending
- **Evidence or links:**
- **Known gaps:**

### Blockers, risks and decisions
What is blocked or uncertain? Which decisions are confirmed, and which are only proposals?

### Next actions
- [ ] Action — owner — target date if known

### Notes / lessons learned
---
