## Journal rules
1. **Record every project work session.** Add an entry whenever you work on the project, including planning, coding, documentation, testing, debugging, reviews, meetings, AI-assisted work, and small achievements.
2. **Record date, time, and timezone.** Use YYYY-MM-DD HH:MM (Asia/Manila, UTC+08:00). For older work with no reliable time record, write “Time not recorded” instead of guessing.
3. **Write what you personally did.** Distinguish your contribution from a teammate's work, an AI suggestion, or a team outcome.
4. **Record outcomes and evidence.** Include relevant paths, commit/PR links, test commands and results, or issue IDs. State clearly when a test was not run or is pending.
5. **Record AI usage and workflow.** Name the AI tool(s), what you asked them to help with, how you supplied project context at a high level, how you reviewed the output, and what you changed or verified yourself.
6. **Record blockers and next steps.** If a task is incomplete, write what remains and what is needed to proceed.
7. **Be factual and useful.** Keep entries clear enough that another teammate can understand what happened later.
8. **Never put secrets or real resident data in a journal.** Do not include passwords, tokens, API keys, private environment values, or personally identifying client/resident information.

Use [Journal-Template.md](Journal-Template.md) for each entry. Journals are working records, not a substitute for approved requirements, testing instruments, or official project documents.
