# 14 · Assistant Sandbox Recipe

Moved here from the development handover (patch 325). It is for an AI assistant that works in a throw-away Linux sandbox (wiped between sessions) and delivers patches; it is not part of the product. The commands assume the repository was cloned over HTTPS and that PostgreSQL 16 can be installed there.

- **Setup:** clone over HTTPS (`git clone https://github.com/ItzVickyyy/Brgy.-Mayondon-LGU.git`; the repository is public); `npm i -g bun`; `uv sync --locked --package app` in `backend/`; `bun install --frozen-lockfile` in `frontend/`. PostgreSQL 16: `apt-get update`, `apt-get install -y postgresql postgresql-contrib`, `service postgresql start` (stops between turns); set the `postgres` password; create `apptest` (pytest) and `appdev` (Playwright server), both with `uuid-ossp`; run `alembic upgrade head` and `python app/initial_data.py` on `appdev`. Env: `DATABASE_URL`, `POSTGRES_*`, `FASTAPI_ENV=development`, `ENABLE_DEV_ROUTES=true`, **`ALLOW_TESTS_ON_THIS_DATABASE=1`**, `SECRET_KEY` (32+ bytes), `PROJECT_NAME`, `FIRST_SUPERUSER(_PASSWORD)`; keep them in a file and `. /path/env.sh` in **every** call. **Do not export `SMTP_HOST`/`EMAILS_FROM_EMAIL` when running pytest** (they enable e-mail, and `test_activity.py::test_account_changes_are_logged_without_passwords` and two other tests that patch `send_email` with `return_value=None` then fail with a `UserCreated` validation error); set them only for the Playwright API. `pwsh` for script tests: unpack `powershell-<v>-linux-x64.tar.gz` to `/opt/pwsh` and link it.
- **Lessons:** Playwright browsers are preinstalled: `export PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers` (`playwright install` does nothing). Start the API and servers with `setsid nohup <cmd> > log 2>&1 < /dev/null &` at the top level of a call, then `sleep`; never `pkill -f "vite --port"` (it kills the calling shell; use `pkill -f "[v]ite --port"`), and stop the API with `kill` of its pid. `frontend/.env` holds `VITE_API_URL=http://localhost:8000`, which a build bakes in and the page's CSP then blocks from `127.0.0.2` (breaks `plain-http-reminder`): build with `VITE_API_URL= bun run build`. The Vite dev server is too slow for the live-backend specs: test the production build served by the API with `PLAYWRIGHT_BASE_URL=http://localhost:8000`. `git stash -u` fails after `git add -N`; use `git worktree add` for a baseline copy (symlink `node_modules`). Backend CORS only allows port 5173. Reset the test database in its own call (`DROP DATABASE ... WITH (FORCE)`, create, `uuid-ossp`, `alembic upgrade head`, `initial_data.py`) and start the API in a separate call; doing both together times out. Never `cut -c` a log containing `›` or `─`; decode in Python.
- **Processes:** background processes can die when the tool call ends; a `setsid nohup` full-suite run survived between calls in the last session (poll the log with `sleep`). Full backend suite takes 4–6.5 min.
- **Frontend-only work:** mocked specs need only the built app on port 8000 (a tiny static server with `index.html` fallback is enough, decoding `%20` in file names). `bun run build` writes to `backend/app/frontend`; re-run after every frontend edit. Mocks: route `**/api/v1/**`; `/users/me` returns an admin; `/lookups/*` returns `[]`; `/dashboard` at least `{ total_issued: 0, by_document_type: [] }`; everything else `{ data: [], count: 0 }`; set `localStorage` `access_token`, `app-language`, `vite-ui-theme`. Run mocked specs with `--no-deps` (skips the login setup) and a root `.env` with `FIRST_SUPERUSER(_PASSWORD)`; `playwright/.auth/user.json` must exist. To check a print layout without a print dialog: stub `window.print`, then `page.pdf({ preferCSSPageSize: true })` or `emulateMedia({ media: "print" })`. Biome lives in the **root** `node_modules` (`../node_modules/.bin/biome`; `bunx` in a git worktree fetches another one). `tsc -p tsconfig.node.json` leaves an untracked `tsconfig.node.tsbuildinfo`: delete it.
- **Playwright rules:** use `expect(page).toHaveURL`, not `waitForURL`, right after `goto`; custom Select via `tests/utils/select.ts` `chooseOption`; never wait on a locator with `.catch`. Full runs need `MFA_ENCRYPTION_KEY`, `LIVE_API_*` (46 `issuance-live` tests, which leave data behind: separate `apptest` and `appdev`) and Mailpit on 8025. A `ZZ test` item left by a failed test must be deleted from `apptest`. `test_rotate_secrets` fails only on a trust-authentication database.
- **Playwright run recipe:** API on `appdev` with `SINGLE_SESSION_PER_ACCOUNT=false` (a bare `fastapi run` defaults to true and breaks the shared admin login): `uv run fastapi run app/main.py --port 8000` via `setsid nohup`, production build (`VITE_API_URL= bun run build`), then `PLAYWRIGHT_BASE_URL=http://localhost:8000 CI= bunx playwright test --project=chromium --workers=1`. Full suite ≈ 6 min at 2 workers on a clean database.
- **Mailpit:** `curl -sL -o /opt/mp/mp.tgz https://github.com/axllent/mailpit/releases/latest/download/mailpit-linux-amd64.tar.gz`, unpack (bare `mailpit` binary), start `./mailpit --disable-version-check` with `setsid nohup` (SMTP 1025, UI 8025); the API needs `SMTP_HOST=localhost SMTP_PORT=1025 SMTP_TLS=false EMAILS_FROM_EMAIL=noreply@example.com`; then `reset-password.spec.ts` runs.
- **Screenshots:** create `mayondon_dev` (uuid-ossp, `alembic upgrade head`, `initial_data.py`, `python -m app.sample_data_cli --residents 120`), run a second API on port 8001 against it (same production build, relative API address), sign in with `POST /api/v1/login/access-token`, put the token in `localStorage` `access_token` (plus `app-language`, `vite-ui-theme`) and shoot with Playwright from a script outside the repository (`createRequire('/tmp/<clone>/frontend/')` to load `@playwright/test`). Read PNGs with the image reader; build contact sheets with PIL. One page with `setViewportSize` is far faster than a new page per width. `app.sample_data_cli` needs a database name ending `_dev`; it makes residents, streets and officials but no issuances (a clearance needs a resident photo and a unique official receipt number).
- **Client regeneration:** export `openapi.json` with the command in `scripts/generate-client.sh` (needs the full env), then `bun run generate-client`; `openapi.json` is gitignored.
- **pip-audit:** `uv export --locked --format requirements.txt --no-hashes --no-dev --no-emit-project --package app --output-file /tmp/requirements.txt`, then `uvx --from pip-audit pip-audit -r /tmp/requirements.txt`.
- **Patch file:** `git add -N <new files>`, `git diff --binary > BMIRMS-Patch-<n>.patch`; prove it with `git apply --check` on a clean tree. If the previous patch is not pushed, build on top of it and say so. End with the command block at the top. Synthetic load: insert rows into `audit_log` with `generate_series` from a `.sql` file (a heredoc to `psql` mangles quotes).
