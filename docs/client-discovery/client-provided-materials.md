## Receipt verification

For each item, the team should privately track:

- Whether the file or physical sample was actually received and can be opened.
- Who in the group has authorized access.
- Whether the client has approved its use for requirements analysis and system development.
- Where the source is stored and who can access it.
- Whether a sanitized copy or blank template can be used for design work.

Do not record passwords, private sharing URLs, resident names, ID numbers, addresses, birthdays, photos, or other personal data in this inventory.

## Data protection

Resident records and ID masterlists must be handled confidentially. Use the minimum data needed for development, prefer fictional test records, restrict access, and do not commit confidential source files to Git. If any personal data is accidentally committed, remove access and notify the project leader immediately; deleting a file in a later commit does not remove it from Git history.
